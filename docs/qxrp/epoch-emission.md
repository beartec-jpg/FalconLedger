# qXRP Epoch Emission

## Epoch Definition

A reward epoch spans `kQXRP_LEDGERS_PER_EPOCH` = **172,800 ledgers** (~7 days at
3.5 s/ledger).  The epoch counter is stored in the `sfEpochIndex` field on the
genesis account root and incremented by the `RewardEpoch` pseudo-transaction.

## Trigger

`RewardEpoch` is generated by the server leading ledger close when
`ledgerSeq % kQXRP_LEDGERS_PER_EPOCH == 0` and the `ProofOfParticipation`
amendment is active.

## Emission Calculation

```
halvingN     = epochIndex / kQXRP_EPOCHS_PER_HALVING   (integer division)
emissionBps  = max(kQXRP_INITIAL_EMISSION_BPS >> halvingN, kQXRP_MIN_EMISSION_BPS)
epochEmit    = treasuryBalance * emissionBps / kBPS_DENOM
```

All arithmetic is 64-bit integer; no floating-point is used anywhere in this path.

| Halving | Approx. years | emissionBps | % of treasury/epoch |
|---------|--------------|-------------|---------------------|
| 0 | 0–4 | 50 bps | 0.50 % |
| 1 | 4–8 | 25 bps | 0.25 % |
| 2 | 8–12 | 12 bps | 0.12 % |
| … | … | … | … |
| ≥ 6 | 24+ | 1 bps | 0.01 % (floor) |

## Distribution

`epochEmit` drops are split among all validators whose composite score exceeds
`kMIN_COMPOSITE_SCORE_BPS` (500 bps = 5 %).  Each validator's share is:

```
validatorShare = epochEmit * validatorScore / aggregateScore
```

Shares accumulate in `sfRewardAccumulator` on the validator's bond ledger object
until the validator calls `ClaimReward`.

## Epoch State Ledger Object

The `ltREWARD_EPOCH` ledger object stores:
- `sfEpochIndex` — monotonically increasing epoch counter
- `sfEpochEmission` — drops emitted in the most recent epoch
- `sfTreasuryBalance` — snapshot of treasury balance at epoch close
- `sfAggregateCompositeScore` — sum of all validator composite scores
